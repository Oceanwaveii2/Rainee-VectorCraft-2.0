Executive decision
This document isolates features that define drawing input, brush behavior, stroke data, and artist assistance. The
core engine owns live stylus capture, prediction and correction, GPU brush rendering, stabilization, vector output,
shape suggestions, stroke analysis, region-based painting, and material/depth guides. VFX-host operations are
covered in the separate Plugins and Bridge PDF.
 • Fast lane: native stylus capture → coalesced samples → short-horizon provisional prediction → immediate GPU
 stroke rendering → correction from actual samples.
• Assist lane: optional local analysis after or alongside drawing; return suggestions as editable paths, masks, or
 maps. Do not block the first visible mark on model inference.
• Reuse-first premise: this technical edition assumes permissions can be obtained and does not rank by licensing.
 Source code, model weights, platform APIs, and host integration availability still determine what can actually be
embedded.
1. Apple Pencil-class responsiveness
Stylus “feel” is a system property, not a single AI filter. It depends on device sampling, OS delivery, event
processing, GPU work, and display scheduling. On supported Apple devices, use the platform’s native APIs. On
other systems, use their native stylus APIs and preserve an equivalent internal input model; hardware behavior
will differ.
1.1 Input-to-pixel path
 • Capture full samples: record timestamp, x/y, pressure, altitude/tilt, azimuth, hover, and available device events.
 Keep raw input immutable. Apple notes that some stylus properties can be estimated and updated later. Apple -
Handling input from Apple Pencil
• Coalesce events: consume high-fidelity samples gathered between UI updates instead of reducing a fast stroke to
 one point per frame. Apple UIKit - Getting high-fidelity input with coalesced touches
• Predict briefly: render a temporary extension from the OS prediction, then replace it when actual points arrive.
 Never commit predicted points as authored geometry. Apple UIKit - Minimizing latency with predicted touches
• Render incrementally: update only the affected canvas area, cache brush stamps and textures, avoid full-canvas
 recomputation during contact, and align work to display timing. Apple - Metal display link and smooth frame rates
• Support hover: show brush size, shape, angle, and expected footprint before contact where the device supports
 hover. Apple Pencil hover support
• Commit on lift: preserve actual input samples; run optional smoothing, simplification, vector fitting, or analysis
 after pen-up.
1.2 Platform implementation
For iPadOS, implement UIKit coalesced/predicted touch handling or use PencilKit where its drawing model
matches the app. Apple documents PencilKit as a low-latency capture framework and provides a drawing-app
sample. For the custom Rainee brush engine, benchmark direct Metal rendering and the exact API path before
deciding which capture responsibilities PencilKit should own. Apple PencilKit documentation • Apple - Leveraging
touch input for drawing apps • Apple - WWDC Introducing PencilKit
For Windows or another target, use the native pointer/stylus interface, capture each device’s raw data, and
normalize it only in a derived representation. Test pressure range, sample rate, tilt, palm rejection, hover, and
pen-up timing per supported tablet.
2. Machine-learning drawing assists
Use machine learning to propose improvements or interpret context, not as a synchronous gate that delays each
stroke. Keep every assist visible, adjustable, reversible, and opt-in per brush or task.

Pressure, tilt, and brush-response personalization
Fit per-user pressure curves and tilt/speed response. Begin with deterministic curves; add on-device
personalization when artist data is available. Preserve raw sensor samples.
Stroke stabilization and cleanup
Reuse a stroke-modeling implementation such as Google Ink Stroke Modeler. Offer low-lag live stabilization and
stronger post-stroke cleanup as separate controls; preserve original stroke and editable result. Google Ink Stroke
Modeler source
Shape and curve suggestions
Fit line, ellipse, polygon, or Bézier candidates after a gesture. Preview the candidate and accept, tune, or reject it;
preserve the original input.
Repetitive-stroke completion
Use nearby marks and image context to suggest the next hatch, fur, hair, or texture stroke. Relevant research:
DrawFromDrawings: 2D Drawing Assistance via Stroke Interpolation and Autocompletion of repetitive stroking
with image guidance. Return editable stroke sequences.
Style-aware stroke suggestions
Reuse available code/models for stroke curvature, width, texture angle, and density. A related stylization
reference is HelpingHand: Example-based Stroke Stylization. Generate candidate paths, not only a flattened
stylized image.
Semantic masks and contour guidance
Suggest subject, object, region, or edge masks; allow paint/add/subtract edits. Feed masks into native fill,
texture, and selective effect tools. Region and texture-aware reference: SIGGRAPH 2013 - Painting by Feature.
Image-to-material approximation
Estimate depth, normals, material response, or lighting from a source image. Reuse models where available,
expose the maps, and allow manual paint-over. Research: SIGGRAPH 2023 - Single Image Neural Material
Relighting and PhotoMat - SIGGRAPH 2023 material generator. Treat values as estimates, not recovered ground
truth.
2.1 Inference placement
The active stroke renderer should use no network calls and no waiting for ML. If local inference is used during a
stroke, run it on a separate queue and never block event collection or presentation. Return suggestions with
editable data, confidence where meaningful, model/version, and source references.
3. Core research trace and reuse plan
3.1 GPU vector brush rendering
Source: SIGGRAPH 2024 paper SIGGRAPH 2024 - Ciallo: GPU-Accelerated Rendering of Vector Brush Strokes,
associated open-source Ciallo open-source vector painting prototype, and the prior Ciallo: the next-generation
vector paint program - Adobe Research. The work bridges editable vector paths with raster-like textured strokes
and GPU brush rendering.
Reuse decision: start from the Ciallo prototype renderer if the code can be built in the target stack. Adapt its
stroke representation and GPU kernels to Rainee’s document model, undo, selection, appearance stack, and
export path. Keep it as a module, not an external application dependency.

Prototype tests: variable width; overlapping texture; vanilla/stamp/airbrush families; vector fill; zoom
consistency; cache invalidation; high stroke counts; tile boundaries; undo/redo; pressure ramps; anisotropic
texture alignment; latency under dense layers.
3.2 Vectorized region-based painting
Source: SIGGRAPH 2013 - Painting by Feature and newer semantic or region-guided painting studies such as
Painting with Paintings - SIGGRAPH Asia 2025 Technical Communications. These methods organize brush marks
around image regions, boundaries, and style cues. The sources are research methods, not ready-made VFX
filters.
Reuse decision: integrate available segmentation/vectorization and stroke synthesis code where it can return
editable paths. Processing stages: select input/region → segment → set boundaries → choose brush and stroke
policy → synthesize/order strokes → preview → accept/edit.
3.3 Stroke movement analysis
Source: SIGGRAPH 2021 Art Papers work SIGGRAPH Blog - Imaginary Stroke Movement Measurement and
Visualization. It analyzes stroke movement and visualization rather than providing an installable commercial
plug-in.
Reuse decision: implement as an analysis module. Measure speed, curvature, acceleration, pressure, tilt, pauses,
and direction changes; use results to expose brush dynamics and offer optional corrective suggestions, not a
hidden artist score.
3.4 Image-to-material approximation
Source: SIGGRAPH research SIGGRAPH 2023 - Single Image Neural Material Relighting, PhotoMat - SIGGRAPH
2023 material generator, and inverse-rendering work. These approaches estimate material/light representations
or relit appearance from limited image input.
Reuse decision: integrate available model code/weights as an experimental local module. Output approximate
depth/normal/material/light maps that native Rainee effects can consume. Provide map visualization, manual
correction, confidence/failure signaling, and an easy return to the unmodified source.

5. Core implementation sequence
 • Instrument stylus capture and display latency on named hardware.
 • Implement raw-sample model, coalesced input, provisional prediction, correction, and immediate GPU preview.
 • Add GPU textured/vector brush renderer and pressure/tilt response.
 • Add deterministic stabilization and shape fitting; validate with actual drawing tasks.
 • Integrate research-code modules for region painting and stroke assistance.
 • Prototype local material/depth inference after the live drawing path is stable.
 
5.1 Acceptance measures
 • Input-to-visible-ink latency distribution, frame pacing, and dropped frames per device.
 • Prediction correction distance; no predicted points remain in committed stroke data.
 • Stroke pressure continuity, corner preservation, texture artifacts, zoom stability, and undo fidelity.
 • Assist acceptance/edit/reject rates and correction effort on defined tasks.

1. Executive Summary
The target is not merely an Illustrator clone. The technical opportunity is to preserve the professional vector-
editing model artists expect while replacing the rendering and brush substrate with a modern, highly parallel 
architecture. Vello supplies a high-performance 2D rendering family; Ciallo supplies a research-backed model 
for editable GPU-rendered vector brush strokes; decades of SIGGRAPH/TOG natural-media research supply 
bristle, watercolor, stroke-synthesis, and differentiable-rendering ideas; and 2024-2026 work adds neural path 
representations, sketch vectorization, cage deformation, style-conditioned SVG generation, sketch segmentation, 
process prediction, and learned procedural appearance.
Primary design rule: keep geometry, brush appearance, simulation state, effects, and AI assistance 
as separate layers. The path must remain editable even when the visible result resembles 
watercolor, graphite, airbrush, or a physically simulated bristle brush.
∩é╖
Compatibility layer: Illustrator-like paths, compound paths, clipping, groups, layers, text, symbols, live 
effects, blend modes, gradients, masks, snapping, artboards, export, and a vector eraser.
∩é╖
Differentiation layer: programmable brush graphs, Ciallo-class stamp/airbrush vector strokes, physical 
bristles, vector watercolor, neural brush styles, live material simulation, and GPU-first effects.
∩é╖
Performance layer: Vello Sparse Strips / GPU rendering, cache-friendly display lists, spatial indexing, dirty-
region updates, multithreaded CPU fallbacks, and progressive-quality simulation.
∩é╖
AI layer: neural vectorization, path repair, text-to-vector, style-conditioned SVG generation, brush-style 
search, sketch segmentation, and optional differentiable optimization.
∩é╖
Non-destructive editing rule: destructive operations such as erase, expand, rasterize, and Boolean 
subtraction should also have live/non-destructive counterparts where practical.

3. Vello as the Rendering Foundation
Vello is best treated as the rendering substrate, not as the entire editor. The current Linebender project contains 
three renderer families: Vello CPU, optimized for multithreading and SIMD; Vello GPU, which performs CPU 
path preprocessing with GPU rasterization/compositing and supports wgpu plus a native WebGL2 backend; and 
the original compute-centric renderer, now retained as an experimental research implementation. Vello CPU 
and GPU share the Sparse Strips architecture. [R1]
∩é╖
Use Vello GPU as the main production path once its required feature coverage is sufficient.
∩é╖
Keep Vello CPU as a deterministic software fallback, headless renderer, test oracle, and low-GPU-
compatibility path.
∩é╖
Keep the compute renderer available as an experimental backend for research features and benchmarking, 
not as the only shipping path.
∩é╖
Do not couple the document model to Vello's current API. Maintain an internal scene/display-list abstraction 
so renderer changes remain survivable.
The compute renderer is still explicitly described as alpha and lists unfinished blur/filter work, conflation 
artifacts, GPU allocation strategy, and glyph caching among known limitations. That is another reason to keep a 
renderer abstraction rather than letting application semantics leak into Vello calls. [R2]
4. Vector Eraser: Illustrator Behavior, Rebuilt as a Modern 
Subsystem
Illustrator's Eraser tool removes arbitrary areas from vector artwork, while its Path Eraser removes portions of 
a path segment. Adobe's current documentation also describes stylus eraser support and pressure-controlled 
eraser width. The replacement editor should reproduce these expectations, then extend them. [R3][R4]

4.2 Implementation strategy
1.
Convert the eraser gesture into a swept 2D region. For a circular eraser this is a Minkowski sum of the 
pointer trajectory and a disk; for angled or pressure-varying erasers it becomes a variable-width swept 
shape.
2.
Use the scene spatial index to find only potentially intersecting objects. This avoids re-running Boolean logic 
across the whole document.
3.
Dispatch by object representation: centerline stroke, closed fill, compound path, live brush stroke, clipping 
path, text outline, or simulation layer.
4.
For ordinary fills, compute robust Boolean difference and clean tiny fragments according to tolerance rules.
5.
For centerline strokes, solve segment intersection in parameter space, split the curve, and retain 
stroke/brush parameters on each surviving interval.
6.
For Ciallo-like brush strokes, erase in stroke/sample space where possible rather than flattening the stroke 
to a polygon soup.
7.
Record the operation as a compact transaction containing changed object IDs and parameter intervals so 
undo/redo is fast.
8.
Invalidate only affected scene/cache tiles and GPU resources.
Research extension: the eraser should be a first-class brush graph too. A watercolor eraser can lift 
pigment, a graphite eraser can reduce deposition while leaving faint residue, and a vector geometry 
eraser can cut exact shapes. One gesture vocabulary, multiple semantic operations.

5.1 Ciallo: the most directly relevant modern paper
Ciallo (SIGGRAPH 2024) proposes GPU rendering methods for vanilla, stamp, and airbrush vector strokes, 
explicitly attempting to bridge raster-style expressiveness with real-time editability. Its authors also released an 
open-source prototype and tutorial resources. This should be treated as a central research pillar for the new 
brush engine. [R5][R6]
∩é╖
Adopt its philosophy: keep the stroke representation editable and regenerate appearance on the GPU.
∩é╖
Study its stamp and airbrush handling as replacements for naive CPU bitmap stamping.
∩é╖
Generalize its representation so the controlling path can be cubic B├⌐zier/spline geometry, not merely a 
polyline-centric editing model.
∩é╖
Integrate its brush representation with the editor's appearance stack, masks, eraser, and undo model rather 
than building a separate paint application.
5.2 GPU-friendly stroke expansion
Levien and Uguray's HPG 2024 work presents a fully parallel GPU-suitable stroke-expansion algorithm using 
Euler-spiral reasoning and a representation designed for parallel processing. This is directly useful for wide 
strokes, pressure profiles, expanded outlines, offset-like operations, and real-time previews of complex brush 
geometry. [R7]
∩é╖
Use GPU expansion for preview and high-frequency stylus updates.
∩é╖
Preserve analytical arcs/curves internally where possible instead of tessellating prematurely.
∩é╖
Cache expansion by path segment and brush parameter range, so editing one node does not rebuild an 
entire long stroke.
5.3 Physical bristle brushes
Adobe research demonstrated an efficient 3D virtual bristle model with strand dynamics, bidirectional paint 
transfer, arbitrary brush-tip shapes, and both raster and vector output. The paper's explicit goal was industrial-
strength use, not a laboratory-only demo. This is an unusually good fit for a high-end illustrator/painting hybrid. 
[R8]
∩é╖
Represent a brush tip as a bundle of bristle strands or strand clusters with bend/spread state.
∩é╖
Drive bristles from stylus position, pressure, tilt, azimuth/barrel rotation, velocity, and acceleration.
∩é╖
Allow dry-brush breakup, paint depletion, bristle separation, load/reload, and bidirectional pickup from 
canvas material.
∩é╖
Offer two output modes: procedural live stroke and expanded/exportable vector approximation.

5.4 Vector watercolor
A particularly important precursor is Adobe's lightweight procedural vector watercolor engine, which used a 
vector-based stroke representation and fast procedural pigment advection to achieve dynamic watercolor-like 
behavior at arbitrary resolution. The work is valuable precisely because it was designed around interactive 
performance and scalable output rather than full fluid simulation. [R9][R10]
∩é╖
Use lightweight procedural watercolor for the default 'fast' watercolor tier.
∩é╖
Reserve heavier shallow-water / pigment simulation for a high-fidelity mode or idle refinement.
∩é╖
Store wetness, pigment, granulation, and edge-deposition as sparse fields attached to stroke regions rather 
than whole-canvas dense buffers.
5.5 Classical watercolor physics still matters
The landmark SIGGRAPH 1997 Computer-Generated Watercolor system modeled translucent glazes, shallow-
water flow, pigment dispersion, paper interaction, edge darkening, granulation, backruns, pigment separation, 
and Kubelka-Munk optical compositing. Its computational details are old, but the perceptual phenomena 
remain an excellent checklist for a modern GPU watercolor model. [R11]

5.6 Real-media capture instead of simulation
RealBrush (SIGGRAPH 2013) showed a complementary strategy: capture real physical media samples, including 
isolated strokes, overlap interactions, and smudges, then synthesize new strokes from those examples. This 
suggests a 'Scan a real brush' workflow for the new editor. [R12]
∩é╖
Photograph or scan representative strokes on real paper/canvas.
∩é╖
Estimate directional texture, opacity/deposition, edge behavior, overlap response, and smudge behavior.
∩é╖
Compile the captured appearance into a procedural or neural brush material that remains driven by 
editable vector paths.
5.7 Neural Brushstroke Engine
NVIDIA's NeuBE (SIGGRAPH Asia 2022) learns a latent style space of interactive drawing tools from unlabeled 
images, supports user-controlled color, compositing, text-based brush search, and style matching. For this 
project, neural brushes should be an optional high-level material generator, not the core geometry 
representation. [R13]
∩é╖
Use latent brush codes as editable brush parameters.
∩é╖
Allow 'find a brush that looks like this artwork' and natural-language brush search.

6. Vectorization and AI-Assisted Geometry
6.1 Deep Sketch Vectorization
Deep Sketch Vectorization (SIGGRAPH 2024) treats vectorization as unsigned-distance-field surface extraction 
followed by neural dual contouring and explicit handling of keypoints and undersampling. The important 
product idea is not just 'trace image' but interactive topology refinement, particularly around junctions and 
sharp features. [R14]
∩é╖
Use for raster sketch 
 editable path conversion.
ΓåÆ
∩é╖
Expose junction/keypoint corrections to the artist instead of hiding all model uncertainty.
∩é╖
Run as a background tool while keeping a conventional deterministic trace option.
6.2 Neural Path Representation
Text-to-Vector Generation with Neural Path Representation (SIGGRAPH 2024) addresses a recurring failure of 
AI-generated SVG: jagged/intersecting paths caused by direct control-point optimization. It learns a path latent 
space and uses a two-stage generation/refinement process. The broader lesson is that AI should operate in a 
geometry-aware path space, not merely optimize raw B├⌐zier points. [R15]
∩é╖
Use a geometry-aware latent representation for AI-generated paths.
∩é╖
Add path-quality priors: continuity, self-intersection penalties, minimum feature size, tangent smoothness, 
and layer semantics.
∩é╖
After generation, always convert to native editor objects rather than leaving an opaque AI blob.
6.3 Style-conditioned vector generation
The SIGGRAPH 2025 style-customized text-to-vector work combines path-level diffusion with image-model 
priors to retain structural regularity while adapting SVG style. This can support coherent icon/asset families and 
style transfer that remains editable. [R16]
6.4 Differentiable vector graphics
DiffVG (SIGGRAPH Asia 2020) makes vector rasterization differentiable, enabling optimization of vector 
parameters against image-space losses. This is valuable for smart vector fitting, automatic cleanup, image-
matching gradients, and AI-assisted refinement. It should live as an offline/assistive optimizer rather than the 
main rasterizer. [R17]
∩é╖
Smart Trace refinement: optimize curves to match a raster reference after topology is established.
∩é╖
Reference-aware path cleanup: improve fidelity while penalizing excess nodes.
∩é╖
Effect fitting: infer gradient/stroke parameters from a target appearance.
∩é╖
Constraint-aware optimization: combine image loss with explicit vector-design rules.

6.5 2026 emerging work: designer-like constraints
DesigNet (2026 preprint) is not a SIGGRAPH paper, but it is directly relevant: it explicitly models curve 
continuity classes and axis alignment/snapping while generating editable SVG outlines. For professional vector 
generation, this is the right direction: AI outputs should obey design-tool constraints rather than simply look 
correct after rasterization. [R18]
7. Advanced Editing Beyond Traditional Illustrator
7.1 Curved-cage deformation
Variational Green and Biharmonic Coordinates for 2D Polynomial Cages (SIGGRAPH 2025) provides closed-form 
coordinates and derivatives for deformation driven by curved cages. This could become a significantly better 
live-warp/deformation system for illustrations than a coarse rectangular mesh. [R19]
∩é╖
Bezier cage warp with direct handles on curved boundaries.
∩é╖
Elastic or conformal deformation modes driven by variational energies.
∩é╖
Non-destructive cage nodes in the appearance/effect graph.
∩é╖
Potentially apply the same deformation consistently to paths, brush centerlines, masks, and embedded 
raster content.
7.2 Sketch segmentation as an editing primitive
InkLayer (SIGGRAPH 2025) segments raster scene sketches into instances and organized depth layers, including 
inpainting occluded instances. This suggests a 'convert sketch into editable scene layers' workflow rather than a 
monolithic trace. [R20]
∩é╖
Select an object from a flattened sketch.
∩é╖
Separate overlapping scene elements into editable layers.
∩é╖
Use segmentation masks to seed independent vectorization passes.
∩é╖
Preserve inferred occluded portions in hidden geometry layers.
7.3 Pattern intelligence
Pattern Analogies (CVPR 2025) learns programmatic pattern edits from an example transformation rather than 
requiring users to manually expose the underlying program. Combined with a procedural pattern node, this 
could make pattern editing substantially more powerful than conventional swatches. [R21]
SIGGRAPH 2024's Generative Escher Meshes is also relevant for non-square periodic tilings. It optimizes 
geometry and appearance under planar symmetry constraints, suggesting a procedural tiling engine capable of 
generating and editing tessellations, not just repeating rectangular tiles. [R22]
One Noise to Rule Them All (SIGGRAPH 2024) learns a unified controllable model of multiple procedural noise 
families and spatial blends. That idea maps neatly into a brush/effect material graph: one 'learned noise' node 
could continuously traverse many noise appearances instead of forcing users to pick separate Perlin/Worley/etc. 
nodes. [R23]

8. AI-Assisted Creation Process
Generating Past and Future in Digital Painting Processes (SIGGRAPH 2025) predicts plausible earlier and later 
drawing states from an existing canvas. In a vector editor this should not replace actual undo history, but it can 
become a powerful ideation feature: infer possible construction steps, propose alternate finishing directions, or 
generate candidate next-stage variants while the real document history remains deterministic. [R24]
∩é╖
Real undo/redo remains transaction-based and exact.
∩é╖
AI 'Past' is clearly labeled as reconstructed process, never confused with actual history.
∩é╖
AI 'Future' can populate a branch browser of possible next stages.
∩é╖
Accepted AI branches are converted into normal layers/objects, not kept as inaccessible flat generations.
9. Materials and Appearance Research
Generative Neural Materials (SIGGRAPH 2025) is aimed at 3D material appearance, but its compact 16-channel 
feature-texture basis and real-time neural decoding are conceptually useful. A 2D brush-material system could 
use a similar compact latent representation for paper grain, graphite, paint body, metallic inks, and complex 
scanned media, with deterministic fallbacks for export. [R25]
∩é╖
Treat neural materials as optional appearance decoders layered on top of explicit stroke geometry.
∩é╖
Bake/export to conventional textures or vector approximations when required for interchange.
∩é╖
Use material LOD: cheap real-time decode during drawing, higher-quality refinement when idle or 
exporting.

16. Important Engineering Boundaries
∩é╖
Do not confuse Vello with a brush engine. Vello is a rendering foundation; brush semantics belong above it.
∩é╖
Do not flatten every painterly stroke to polygons. Keep the generative representation and cache its rendered 
form.
∩é╖
Do not make AI mandatory for basic editing. Professional drawing latency must remain deterministic.
∩é╖
Do not use a single dense full-canvas fluid simulation for watercolor. Use sparse, tiled, local simulation.
∩é╖
Do not let export formats define the internal architecture. The internal format should be richer, with 
explicit bake/expand rules for SVG/PDF.

Do not treat undo as snapshots of the entire document. Use transactions, revisions, and structural

behind the same scene abstraction.

18. Final Architecture Recommendation
Build the editor as a native vector document/geometry system with Vello behind a renderer abstraction. Treat 
Ciallo-style GPU strokes as the default advanced brush representation; add physical bristle and vector-
watercolor engines as material/simulation nodes; implement Illustrator-compatible erasing at the geometry 
layer plus live erasing in the effect graph; and attach AI tools to editable representations rather than allowing 
them to bypass the document model.
The north-star interaction is simple: an artist should be able to draw one editable curve, render it as 
clean vector ink, graphite, dry brush, watercolor, or a neural style; erase it with Illustrator-like 
precision; warp it with a curved cage; vectorize or repair it with AI; and still come back later to 
move a B├⌐zier handle without rebuilding the artwork from scratch.
